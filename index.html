LabCheck

A checker for liquid-handling protocols.

A liquid handler does what the protocol says. If the protocol asks a 20–300 µL pipette for 15 µL, or takes 60 µL from a tube with 40 in it, the robot just goes ahead. Usually you notice when the plate looks wrong.

LabCheck runs the protocol in software before the robot does. It keeps count of the liquid in every tube and well and lists the steps that can't work as written. You don't need a robot or any lab data to use it.

What it checks

  1. PIPETTE_RANGE: the volume is within the pipette's range.
  2. REAGENT_EMPTY: the source still has enough left when the step runs.
  3. WELL_OVERFLOW: no well ends up over its capacity.
  4. WELL_MISSING: the well exists on that plate (there is no I1 on a 96-well plate).
  5. CONTROL_MISSING: the negative and positive control wells get filled.
  6. DEAD_VOLUME: optional. A source isn't emptied below the volume the pipette can't reach. Off in the figure above.

Each failure is listed with its step number and a one-line reason.

Where this comes from

I'm building this over four weeks. It starts from the Laboratory Automation Protocol format in this ACS Synthetic Biology paper. First I reproduce the paper's format, then I add the rules, then I break protocols on purpose and count how many the checker catches. Method

Protocol in, verdict and list of failures out.

  1. Parse. Read reagents, volumes, labware and steps from YAML or JSON, using the LAP format.
  2. Simulate. Go through each transfer and update the volume in every source and well.
  3. Check. Test every rule after each step.
  4. Report. List the step, the rule and why it failed.

Rules

CodeFails when
PIPETTE_RANGEThe volume is below the minimum or above the maximum
REAGENT_EMPTYThe running stock of a source drops below zero
WELL_OVERFLOWA well's accumulated volume goes over its capacity
WELL_MISSINGThe well is outside the plate's rows and columns
CONTROL_MISSINGA required control well is never dispensed into
DEAD_VOLUMEA source is left with less than its dead volume (optional, off by default)

An example step

reagents:
  buffer: {labware: reservoir, well: A1, ul: 1000}
  dye:    {labware: tubes,     well: A1, ul: 40}
controls: {negative: A1, positive: A12}
steps:
  - id: 4
    transfer: {from: dye, to: B1, ul: 15}
# step 4 fails: 15 µL is below the 20 µL minimum

How I'll know it works

Unit tests only show the rules run. To see if they catch mistakes, I take a valid protocol, put in one known error, and check that LabCheck reports that error code. The score is how many it catches for each type of error. I also run the untouched protocols to count false alarms.

What it will not catch

It knows nothing about viscosity, evaporation, collisions on the deck, timing, or whether the experiment makes sense biologically. A pass only means the protocol agrees with itself. The assay could still fail.

Planned stack: Python, pytest, YAML/JSON protocol files, and the Opentrons API where it fits.

Report

Draft. Orange parts aren't written yet.

Abstract

Liquid handlers run protocols exactly as written, so a mistake in the protocol becomes a mistake in the experiment. LabCheck simulates a structured protocol, checks it against six rules before it runs, and explains each failure. I measure how well it works by injecting known errors into valid protocols. Final figures to come.

Background

The Laboratory Automation Protocol format, described in ACS Synthetic Biology, gives automated experiments a shared structure. LabCheck adds a validation step on top of it. It is meant for lab automation and assay development, where the run only works if the protocol was right to begin with.

Design

Four parts: a parser, a transfer simulator, a rule engine and a report writer. The method page describes them.

Evaluation

Error injection gives a detection rate for each error type, and clean protocols give the false alarm count. A first test is on the results page. Full evaluation to come.

Limitations

The checker only finds what its rules describe. It doesn't model liquid properties, deck layout, timing or biology. A pass means the protocol is consistent with itself, nothing more.

Glossary

Lab words used on this site.

Assay
A lab test that measures something, such as how much of a molecule is in a sample.
Dead volume
Liquid left in a tube or reservoir that the pipette cannot pick up.
Error injection
Adding one known mistake to a correct protocol to see whether a checker notices it.
False alarm
The checker flags a protocol that was actually fine.
LAP (Laboratory Automation Protocol)
A structured way to describe automated experiments, from the paper this project starts with.
Liquid handler
A robot that moves measured volumes of liquid between containers.
Negative control
A well that should show no signal, so you can see the background level.
Pipette range
The smallest and largest volumes a pipette can measure reliably, for example 20–300 µL.
Plate
A tray of small wells. A 96-well plate has rows A–H and columns 1–12. A 384-well plate has rows A–P and columns 1–24.
Positive control
A well that should show a signal, so you know the assay can work.
Protocol
The ordered list of steps an experiment follows: what to move, how much, and where.
Reservoir
A trough holding a bulk reagent that the pipette draws from.
Well
One small cup in a plate, named by row and column, such as B3.
µL
Microlitre, a millionth of a litre.
